# Hermes App 设计需求

## 1. 已确认的目标

来源为本项目 README 所列设计线程。以下是 Jamie 明确表达或在讨论中确认的产品目标；技术候选与尚未确认的交互放在第 5 节。

### R01 独立多端客户端

桌面 Settings 采用左侧导航、右侧内容。关键页面为 Default agent model、Font size、Shortcuts 和 Connections。Connections 展示已保存连接列表，支持添加配对、确认删除和查看真实连接状态。添加不替换现有连接；删除只清理目标连接的本机凭据、tab、草稿和待发队列，不删除服务端对话。Sidebar 直接展示各连接的 Project 和近期 Session，以连接名作为次要归属说明，不要求先切连接。每个 tab 固定绑定连接身份和 Thread ID，切换连接的 tab 不重建其他页面。新建 Project 必须明确显示并绑定目标连接；多连接时要求主动选择，不能跟随 tab 切换改变归属。删除后重新配对按新连接处理，清除原连接本机草稿与待发队列是预期行为，不保留原地恢复流程。默认模型使用明确选定 Agent 的真实配置接口，不存本机假选择。字号复用设备偏好。Shortcuts 首版列出已支持的固定按键，不宣称支持自定义绑定。Find a session 保留快捷键入口；Delete project 移到 Project 编辑页并保留确认。候选实现、自动验证和未发布边界见 [桌面 Settings](desktop-settings.md) 和 [桌面多连接管理](desktop-connections.md)。

2026-10-05 已确认多 Hermes 连接扩展到手机：所有已配对 Hermes 同时连接，任一连接失败不影响其他。手机与桌面一致，以扁平 Project 列表为主导航，Hermes 名称作为次要文字，不设 Hermes 分组层级或切换器。Project 显示数字：其下有“已完成未读”结果的 session 数（同一 session 只计一次，不计归档）；已读规则不变，进入列表不清零。旧单连接迁移为 primary，不要求重新配对。实现与验证边界见 [多连接](multi-connection.md)。

桌面所有添加的附件都有小缩略图，覆盖已发送消息、Session 附件草稿及 New chat 本地选择/粘贴的文件。受支持的图片显示真实缩略图；PDF、HTML、文本及其他文件显示文件类型图标，不能伪造内容预览。保留大图、预览、移除、保存及外部打开行为；本地缩略图不得提前创建会话或上传。候选与验收边界见 [附件小缩略图](desktop-session-composer.md#attachment-small-thumbnails-candidate)。

已确认：手机和桌面点一次即可在 App 内查看常见内容，包括 Markdown（渲染）、HTML、文本/代码、PDF、图片、视频、音频及网页链接；不支持的格式明确说明。手机网页链接在 App 内浏览器打开。范围、平台限制与验收见 [App 内文件预览](file-preview.md)。

桌面增加可收起的右侧 sidebar，用于附件预览、查看生成的 HTML 页面及浏览网页。右侧浏览器 UA 必须使用当前 Chromium 主版本对应的标准 Chrome 格式，不含 Hermes/Electron 标记；HTTP 请求与页面 `navigator.userAgent` 一致。候选能力、文件类型/资源限制及真机边界见 [桌面右侧预览与浏览器](desktop-macos-v1.md#当前候选右侧附件预览与浏览器)。

桌面 Session 内容的行内代码、单行/多行 fenced 或缩进代码块，以及已有安全命令块，统一使用 `rgb(245,245,250)` 背景色；不改变文字颜色、字号、间距或行为。此要求覆盖此前蓝灰代码背景，仅限桌面。候选及验证边界见 [代码背景色](desktop-session-composer.md#desktop-session-code-background-correction)。

桌面版提供简单的本机字号设置，**默认 16px**。Settings 中通过 Text size 选择 12–24px，立即生效并在 App 重启后恢复；可一键恢复 16。同时覆盖界面与内容，包括输入框、导航、表单、状态、标签、时间、草稿标注、正文、代码和工具命令。不做整页缩放；只修正已固定的文字行高及对应标签裁切容器。间距、栏宽、图标、按钮尺寸及手机版不变，不增加字号快捷键或服务端字段。此要求取代此前 18.4px 固定候选、14px 默认值和旧桌面草稿 11px 的字号要求，不改变草稿位置、红色和行为。候选验证与未发布/真机边界见 [桌面 Session 内容](desktop-session-composer.md#desktop-default-font-size-candidate)。

最终提供可独立安装的桌面客户端与手机客户端，连接 Hermes。界面借鉴 Discord 成熟设计以缩短开发周期，不以复制 Discord 或兼容其协议为目的。具体操作系统及首发顺序待定。

App 自带界面与所有提示统一用自然英文，包括状态、错误、配对/权限说明、工具操作标签及阅读器控件；用户输入、用户命名和 Agent 回复保持原文，不自动翻译。系统/Expo Go 自有界面由各自语言设置控制。实施及验证见 [内置文案统一英语](m1-english-ui.md)。

桌面、手机 Session 内容页及手机全屏阅读模式的表格最大宽度为当前页面的可用内容宽度；引用、列表和用户气泡中的表格按局部可用宽度计算，不撑宽消息或页面。表格列在该宽度内分配，单元格内容自动折行；长词、链接和行内代码也折行，保留完整原文、所有行列及选择/复制能力。此要求取代此前保留宽列、不压缩列宽并在表格内部横向滚动的规则。手机独立表格阅读器及全文 HTML 失败后的原生回退遵守相同规则；代码块和图表的滚动行为不变。实现与验收边界见 [表格容器宽度](markdown-table-width.md)。

纯文本代码块（`text`、`txt`、`plaintext`、`plain`、无语言标记的 fenced 块及缩进代码块）在桌面 Session、桌面 Markdown 预览、手机聊天和手机全屏阅读中自动换行，保留原有空格与换行；带编程语言的代码块仍保留原行并横向滚动。此要求取代上一条中“代码块滚动行为不变”对纯文本代码块的适用。见 [纯文本代码块自动换行](code-block-wrap.md)。

桌面和手机每条最终回复的消息工具栏最右侧显示生成它的原始模型 ID，来源为插件在 `post_llm_call` 记录的本轮实际模型（含备用切换）。旧回复不补写；只要求 Hermes App 发出的消息有模型。见 [回复显示生成模型](reply-models.md)。

桌面侧栏搜索框下方显示前 5 个常用 label（使用该 label 的 session 最多者优先，相同时最近使用优先），点击加入搜索、再点移除。手机 Recents 页提供同样的搜索框和 quick label filter，搜索范围为全部 Thread。见 [桌面 Session 搜索](desktop-session-search.md) 与 [手机 Recents](mobile-tabs-recents.md)。

已确认 Channel 工作空间方向（客户端与插件候选已有实现，发布/真机另行验收）：每个 Channel 绑定稳定的服务端文件系统目录，Channel 内的资料与工作文件以该目录为归属；根目录 AGENTS.md 是长期工作约定，Channel 界面提供真实文件编辑入口。Context 是简短摘要，不与 AGENTS.md 自动互相覆盖。共享目录不共享 Session 历史、不意味着安全沙箱；文件存在不等于全部自动进入模型上下文。既有文件迁移、完整文件管理及原生执行 CWD 绑定仍是后续工作，不修改核心或先放空入口。手机 Files 浏览/预览、同一真实 AGENTS.md 的原版本条件保存、冲突/草稿保护、capabilities 门控与验证边界见 [手机工作空间入口](mobile-workspace-entry.md)。

桌面消息输入框及 New chat 首条消息输入框支持 Cmd+V 粘贴剪贴板文件和截图。纯文字仍使用原生粘贴；有文件时不把剪贴板附带的文字路径插入正文。既有 Session 粘贴后上传到当前 tab 的附件草稿，不自动发送；New chat 粘贴先保留本地文件，明确发送时才创建会话并上传。沿用每条消息最多 8 个附件、每个 1 byte–10 MiB 的限制。支持无磁盘路径的图片字节，不开放通用剪贴板读取或任意 IPC。已随 Desktop v0.1.30 发布；实现、校验及真机边界见 [桌面粘贴附件](desktop-session-composer.md#desktop-clipboard-attachment-paste)。

桌面新建 Session 弹窗提供 Channel 选择和附件；Channel 树 hover/focus 工具栏可打开同一弹窗，默认选择该行 Channel。桌面会话输入栏沿用移动端的紧凑多行输入、同排附件/停止/发送控件设计。桌面与手机版最新确认规则为：隐藏发送者名字；用户消息靠右，最大宽度 80%，正文左对齐，浅灰底，宽高随内容变化。最新宽度规则替代此前 60% 上限；保留短消息自适应、共享外侧边距及富文本局部滚动，不新增对齐设置。手机隔离候选与真机边界见 [手机用户消息样式](mobile-user-message-block.md)。桌面候选与附件语义见 [桌面 Session 输入与用户消息](desktop-session-composer.md)。

最新确认的时间显示规则：桌面和手机均隐藏 Agent 回复的时间，包括公开说明、工具记录、最终回复及直接回复；不保留空时间标题。日期按设备本地日历日居中分隔，同日不重复；当年显示英文月日，其他年份增加年份。用户消息气泡右下角只显示 `HH:mm`，辅助功能完整日期和原存储时间不变。系统通知和会话目录时间保持原有规则。仅改变呈现，不删除存储时间或影响消息排序。该规则替代逐条用户消息显示完整日期的旧规则；隔离候选分支 `fix/message-date-working`。

消息进入本地发送队列后，先显示 Agent 响应区域原有的 `Working` 标题，不等首条公开说明或工具调用。正常发送、处理和完成的 reaction、单勾与双勾全部移除，不另加顶部状态或完成提示。公开过程到达时使用同一呈现区域，保留已有 `Working / Worked` 折叠交互；没有过程的直接/最终回复不留下空的完成区域。失败、结果未知、待审批/回答和取消操作仍明确呈现。提前标题只表示请求在等待处理/处理，不证明模型已经开始；不伪造 assistant 消息、工具记录、进度或执行耗时。

候选验证：手机 TypeScript、75/75 测试及顺序 iOS/Android Expo JS 导出通过；桌面 TypeScript/构建、41 通过/1 原生 Electron 门控跳过；共享客户端 21/21 测试通过。新增移动生产组件检查修改前失败、修改后通过；实际 Chromium 验证提前标题、首条输出合并、追加、final/direct、失败/取消/审批、冷读状态及窄窗口富文本时间布局。UTC、洛杉矶及印度时区的日期/时间定向检查均通过。私有证据在 active Channel workspace 的 `working-*.log`。未合并、发布或重启服务；手机导出不是独立安装包，iPhone/macOS 真机视觉、键盘与滚动验收仍待完成。锁文件、插件、Hermes 核心及运行目录不变。隔离手机依赖安装报告既有锁定依赖 29 项审计问题（10 moderate、19 high），本轮未自动升级依赖。AGENTS.md 的相关规则更新因授权提示超时未应用，不能声称已同步。

公开过程采用可折叠标题，标题下方加分隔线。标题右侧箭头使用两端共用的本地图标字体，不使用普通文字字符；展开时向下，折叠时向右。真实运行时显示 `Working`；明确最终回复到达时立即折叠，标题显示 `Worked for {时间长度}`，用户可重新展开。最终回复、用户追加和系统通知仍保持可见及原位置。时间长度按当前已加载首条公开过程记录到最终回复的时间差计算，不等于服务端运行耗时；时间缺失或倒序时显示 `Worked for —`，无最终标记且未运行的记录显示 `Work recorded`。内部推理仍不展示。旧历史和分页只处理实际加载数据，不补造缺失过程。候选及验收边界见 [桌面 Session 内容](desktop-session-composer.md)。

### R03 Channel Description 公共上下文

Channel 的 Topic / Description 可保存背景、目标、约束及必要参考提示。创建新 Thread/Session 时，将这些内容设置为该 Session 头部的公共上下文；后续对话沿用已有 Session 上下文，不要求每条用户消息重新携带或重复追加 Description，也不要求逐轮重新读取 Channel 说明。说明不只是展示文字，应在该 Session 执行时实际生效。

只有全新的用户会话才注入一次 Channel Description。因时间或长度触发压缩后，直接沿用 Hermes 压缩后的上下文，插件不补入、不恢复原文快照，也不因压缩生成新的物理 Session ID 而再次注入。共享 Channel 提示不等于共享其他 Thread 的全部历史。

验证重点是全新会话初始化一次，以及续聊、冷恢复、时间/长度压缩后没有插件再次注入；不要求压缩后仍逐字包含 Description。Hermes 自身保留或传输已有上下文不需要插件干预，也不应主动删除其中已有的说明。

### R04 连续的用户历史

手机 Session 首次加载历史后自动定位到底部。附件来源进入仍定位精确目标；返回存活页面保留阅读位置。Session 底部输入框按当前字号增长，最多显示六行；超过六行后在输入框内滚动，不截断草稿。该要求取代原固定 120pt 外层高度上限。实现与验证边界见 [底部输入与定位](m1-composer-latest.md#session-initial-tail-and-six-line-composer)。

用户看到稳定、连续的对话，而不是运行时 session 的原始记录。底层 session 可以压缩、续接或切换，但：

- 用户原始消息、面向用户的助手回复、附件与产物不被压缩摘要替换。
- 内部提示、压缩摘要、idle compaction 维护过程不进入普通聊天正文。
- 用户需要知道的记忆/Skill 自检结果与 context compression 状态作为独立轻量系统通知显示，不冒充 Hermes 回复，也不写入模型历史。一次压缩过程原位更新同一通知，完成态保留；例行压缩状态是否发出仍服从 Hermes 的通知配置。
- 重开对话、断线重连、切换设备后，内容不丢失、不重复、不乱序。
- 实时显示和从历史重新加载的最终内容一致。
- 打开已有 Session 时，通过一次 HTTP 请求读取完整原始历史，不先加载最新一页，也不在客户端或服务端循环分页。普通进入定位到最新消息；附件来源进入定位到精确目标消息。
- 返回仍存活的页面保留内容和阅读位置，不重复加载。实时更新和重连继续使用完整快照。资源超限明确失败，不截断后宣称完整。附件文件仍按需下载。详情见 `docs/full-history-loading.md`。此要求取代原「进入一页、首次展开才全量加载」策略；当前实现为未发布候选。
- 首次消息读取及全量历史加载显示明确 `Loading messages…` 提示和动画；减少动态效果时保留静态提示，缓存页面返回不显示虚假加载。

### R05 异步消息同步

手机推送已确认规则见 [推送设计](push-notification-design.md)：插件在完成、待审批/回答、需处理的失败和主动结果事件点统一发送，不依据当前页面或跨端已读压制。客户端只在前台查看目标 Session 时抑制横幅和声音；查看其他 Session 时仍提醒，包括审批。后台由操作系统展示。不做跨端通知压制、撤回或清除，不改变既有聊天同步、共享已读及审批竞态控制。供应商与签名路线待确认；Jamie 当前尚无 Apple Developer 账号。

2026-10-02 新增已确认的窄范围例外：session list 提供跨设备共享的“已完成未读”标志。该状态属于目录订阅数据，服务端持久保存完成结果版本及共享已读版本；任一设备在前台实际显示对应结果后确认，其他端通过目录更新清除。旧确认不能清除新结果。不恢复未读计数、通用消息已读位置、未打开会话正文读取或本地历史缓存。此项覆盖下文旧范围中“不提供跨设备已读”的绝对表述；实现与验收见 [已完成未读目录状态](completed-unread-directory.md)。

最新已确认范围见 [存活 session 页面](live-session-pages.md)：目录及运行状态常驻；所有存活 session 页面同时拉取和实时订阅各自内容。打开另一页面、失焦或覆盖不清理旧页面。当前客户端按连接身份＋稳定 Thread ID 保持唯一页面，返回原页面不重开。真正销毁、身份移除或服务端确认目标失效才释放。未打开的 session 不预取正文；不新增客户端 SQLite 历史库、事件重放或定时业务读取。后台保留现场，恢复核对每个已加载窗口。服务端仍权威保存历史和任务；凭据与未确认发送安全持久保存。冷启动不恢复旧历史。共享实时协议见 [实时订阅重构](open-session-live.md)。

后台现场保留适用于所有存活 session 页面：切后台、失焦或被另一页面覆盖，不清理时间线、历史窗口、阅读位置、草稿、附件或阅读器现场。只暂停后台连接和读取；回前台核对各窗口，保持阅读锚点和跟随状态。页面真正销毁、身份移除或服务端确认目标失效才释放对应内容。不扩大为系统强杀后的历史持久缓存。

客户端连接是观察与操作入口，不应决定任务是否存活。

- Hermes 接收并持久保存消息后确认；确认接收与执行完成是两个状态。
- 关闭客户端或网络断开不应仅因离线而取消已接收的正常任务。
- 在线设备订阅目录/运行状态及当前打开会话的消息；离线恢复重新读取，不逐事件回放。
- 用户从不同设备发送的内容进入同一 Thread。
- 支持后台任务及定时任务的主动结果投递，没有当前请求也能接收消息。
- 不提供未读计数或跨设备已读同步；系统推送是提醒，Hermes 保存的消息才是权威内容。

### R06 服务职责

Hermes 实现项目结构、存储、历史维护、公共提示与运行管理。通信 adapter 负责客户端通信，不另建权威业务存储。客户端仅在内存保留轻量目录与存活页面内容；凭据、待确认发送和用户草稿单独处理，不建立本地聊天历史数据库。

### R07 最短可靠开发路径

优先复用 Hermes 现有 API、桌面代码和共享前端逻辑。需要的能力应以现有源码和验证为依据，不因为借鉴 Discord 而引入协议兼容、社交体系或额外服务。

### R08 插件扩展，不修改 Hermes 核心

不为 Hermes App 修改 Hermes 核心源码。已有能力通过现有接口复用；客户端需要的新增服务端能力由 Hermes plugin 实现。不得用运行时 monkey patch、复制修改核心模块或客户端专用 fork 替代插件扩展。插件扩展点不足时先报告限制与替代方案，不能默认获得修改核心的授权。

## 2. 为满足目标必须明确的正确性约束

这些是研发验收约束，不表示当前 Hermes 已经实现。

- 稳定 Thread 身份不能绑定到某个会变化的物理 session ID。
- 消息具有稳定身份和顺序；重试同一发送不重复消息/执行，新的发送不误判为旧请求。
- 重新打开或重连必须从服务器读取当前状态，应对长时间离线和服务重启；客户端不依赖事件回放或本地历史库。
- 流式草稿、已确认内容与最终消息可合并去重；不用为每个 token 建永久业务事件。
- 审批/澄清只能对仍有效的请求生效；一端作答后其他端同步收起，过期回答不能触发执行。
- 服务重启后，已接收消息不得丢失，执行状态必须准确；不能盲目重跑可能有副作用的动作。自动恢复执行的范围在 P0 决定。
- 普通网络断线与正常超时、卡死、人工停止分开处理；离线执行不是允许任务无限运行。
- 真实历史已被外部删除时不得伪造；迁移限制和缺失内容必须说明。

## 3. 客户端功能规划

以下为建议的首个完整版本清单，尚不代表所有细节已获确认：

- Channel / Thread 创建、改名、排序或归档，公共说明查看与编辑。
- 消息时间线、历史分页、引用、复制、附件上传下载、搜索定位。
- 流式回复、可折叠执行进度、停止、运行中追加指令。
- 审批、澄清、连接状态、发送确认及失败重试。
- 运行状态、系统通知、点击通知进入对应 Thread；不包含未读与跨设备已读。
- 桌面多栏布局、快捷键和文件拖放；手机导航、键盘安全区域、相册与文件选择。
- 凭据安全保存、退出登录、客户端缓存按连接身份隔离。

内部运行记录默认不展示；工具进度的折叠形式不应把内部维护消息带进正文。系统通知只接收服务端识别并绑定到精确 Thread 的有限类型，不能因存在 Thread ID 就把任意 adapter 文本写入历史。

## 4. 最终用户场景

在桌面 Channel 新建 Thread，自动获得 Description。发送任务后关闭全部客户端，Hermes 继续执行，期间可能发生上下文压缩。手机收到通知，打开后读取连续完整内容并继续对话；桌面重开后读取相同内容和当前执行状态。没有压缩交接文本、缺失消息或重复执行，也不要求客户端在关闭期间保存消息历史。

## 5. 建议与待决项

### 已提出但仍需确认的默认建议

- Description 修改对已有 Session 头部是否生效、何时生效另行决定；不默认逐轮热更新或自动重写已有 Session。
- Channel 说明属于项目级指令，不能覆盖 Hermes 全局安全和授权约束；编辑权限由服务端控制。
- 优先用现有 Electron/React 基础衍生桌面客户端；共享前端用于移动原生容器的方案须验证后定。
- 首版先解决个人多设备体验；多人协作权限不自动纳入范围。

### 在对应阶段前确认

- 桌面与手机目标系统：macOS/Windows/Linux、iOS/Android 的必选范围和首发顺序。
- 手机是否采用共享 React + 原生容器；验证性能、推送、键盘、附件后再定。
- Channel 与现有 Hermes Project 的具体映射，是否需要分类/论坛视图。
- 同时发送多条指令的排队/追加/打断行为；明确提示，不能悄悄丢弃。
- 消息编辑/删除是展示修改还是重新执行；首版不得把编辑默认变成破坏历史的回滚。
- 已有 Discord/Telegram/桌面历史是否迁入；不默认授权抓取或改写。
- 首版远程 Hermes 连接方式、配对认证、推送服务与隐私策略。
- 安装分发、签名、更新与应用商店路线；账户及公开发布单独授权。

## 6. 非目标

不重写 Agent，不模拟 Discord 服务或协议，不构建完整社交/角色/语音房体系。Web 演示不是独立手机 App 的替代交付。不因项目初始化自动开展生产部署。
