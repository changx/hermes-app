# Session 自动滚动到底部

## 范围

用户要求：普通打开 Session 后显示底部；在 Session 内主动发送后恢复底部跟随。

候选分支：`fix/session-auto-bottom`。基线：`c39bd30`。卡片：`t_dfad30dd`。

只修改手机和桌面客户端。未合入 main、推送、发布或重启服务。未修改插件、协议、Hermes 核心、依赖或聊天数据。

## 实现

- 手机：内容尺寸事件始终核对底部。不能因为此前 onScroll 已记录相同高度而跳过。滚动事件报告新内容高度、视口高度或底部 inset 时也触发核对。
- 手机：视口及键盘控制器 inset 变化触发核对；键盘动画结束后补滚。主动发送保留即时定位，并在下一帧及新用户行提交后再次核对。
- 手机：沿用原生 scrollToEnd 和原有手势、后台、失焦保护。用户上翻、附件来源定位及返回仍存活阅读页面不强制跳底。
- 桌面：ResizeObserver 观察真实内容容器和视口。图片、图表等延迟渲染完成后，在跟随状态下滚动到真实底部。
- 桌面：尺寸变化引起的滚动不解除底部跟随。消息成功进入本地发送队列后，恢复跟随；保存失败保留草稿和阅读位置。

正常阅读旧消息时，Agent 新回复和内容尺寸变化不抢走位置。主动发送是恢复跟随的明确操作。

## 修正：接近底部时的跳动

现象：向下滚动到接近底部后，页面再跳到最底部。手机和桌面都有。

原因：手机端在距底部 80pt 内、桌面端在 48px 内即恢复底部跟随。手机端"回到最新"按钮随即隐藏，输入区高度变化，或任意内容/布局事件触发 `scrollToEnd`；桌面端跟随状态变化后布局效果直接设置 `scrollTop` 到底部。剩余距离一次补齐。

修正：用户滚动只有真正到达底部（手机容差 2pt，桌面容差 2px，吸收像素取整）才恢复跟随。上翻立即解除跟随的规则不变；主动发送和点击回到最新仍恢复跟随。

验证：手机新增组件回归，停在底部上方 40pt 时内容/布局事件不再滚动，到达底部后恢复跟随。桌面 Chromium 回归新增 3 项检查（共 15 项）：停在底部上方 30px 不跳、内容增长保留位置、到达底部后恢复跟随。两个用例均在修正前失败。iPhone 与 Mac 真机手感待验收。
