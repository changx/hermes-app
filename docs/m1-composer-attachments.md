# 多附件、系统选择与输入状态

## 本轮需求与决定

- 全屏文章沿用系统长按选中和复制，不新增自制高亮/复制浮层；避免外层双击手势干扰全屏选择。
- 输入区可选择多个文件，图片显示缩略图、点按看大图；非图片显示文件名/类型，不伪造图片缩略图。消息发送后与历史重读仍能预览附件。
- 粘贴图片使用系统支持的原生粘贴入口。当前 Expo Go 内普通 RN TextInput 是否支持图片粘贴须核对；如需要独立原生构建，不把显式粘贴按钮宣称为输入框长按菜单粘贴。
- 复用现有认证附件上传/下载与消息附件 ID 协议，不引入新存储平台，不改 Hermes 核心。服务端现有限额沿用（最多 8 个附件，类型/单文件大小以实际 API 为准）。
- 上传完成后同附件 ID 随持久 outbox 发送，重试不可变，允许只有附件没有正文；上传/保存失败保留选择和草稿，不误报发送成功。
- 输入框上方靠左显示 `hermes is typing...` 与三个依次缩放的小点，只根据当前话题真实 running 状态显示；待审批/结束/断开时不伪造正在输入。遵从减少动态效果，卸载/后台停止动画。保留消息 reaction。

## 验收

- 生产回调：多选/取消/移除/失败、图片粘贴、预览开关、全屏系统选择、真实状态显隐与动画生命周期。
- 传输与可靠性：二进制内容、认证不出 URL、附件 ID/顺序/内容随持久重试与冷启动保持、纯附件消息和旧文本记录兼容。
- 主控复跑移动测试、TS、SDK相关检查、双平台导出；仅已验证客户端更新隔离 Expo。核心与 Gateway 不顺带改动。
- 自动化、开发入口发布与真实 iPhone 手势分别记录，不以 mock/导出代替手机验收。

## 实现与主控验证

- `AttachmentComposer` 提供多选图片、文件和显式粘贴入口；最多 8 个附件、单件最多 10 MiB，并发上传/下载最多 3 个。图片有缩略图与全屏预览，非图片显示文件名；小型文本可查看正文，PDF/Office 等不提供内嵌大图渲染。
- `MessageAttachments` 通过现有鉴权接口取得字节并写入应用缓存，不把认证放到图片 URL。失败可重试；卸载清理本组件创建的预览缓存。显式移除未提交附件可请求删除，切换话题或提交后清空不删除可能已进入持久 outbox 的 ID。
- 附件描述符随正文分块持久化；保留旧纯文本记录格式。重试沿用同一消息 ID 与附件 ID、顺序，不重复上传。原生二进制传输使用 percent-utf8 文件名头，服务端严格解码；纯附件消息经过原有事务和幂等校验。
- 全屏文章禁用入口双击识别，保留原生文本选择；输入框上方显示真实 running 状态的 `hermes is typing...` 和三个依次缩放的小点，离线/待交互/后台不伪造动画，遵从减少动态效果。
- 主控完整验证：移动端 **159/159**，移动 TypeScript，通过固定核心基线的 SDK 检查（24 项单元 + 17 项可靠性）、P1 **122 passed**，iOS 和 Android Expo 导出、`git diff --check` 均通过。依赖审计为 10 moderate、0 high、0 critical，未宣称零告警。
