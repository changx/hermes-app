# M1 Agent 状态 reaction

## 已确认范围

Jamie确认借鉴Discord reaction，主要用于表达Agent真实状态，不做用户emoji选择、计数、点赞或社交功能。展示附着在对应用户消息下，在同一位置更新，不新增状态聊天消息。当前先实现，部署须按明确授权执行。

## 状态与身份约束

- 服务端收据 queued → ⏳ 排队中；running → ⚙️ 处理中；completed → ✅ 已完成；failed → ⚠️ 执行失败；interrupted → ⏹ 已停止；unknown → ⚠️ 结果待确认。
- 对应收据存在pending审批/澄清时显示 ⚠️ 等待审批/等待回答，不能把已结束收据误标为仍待处理。
- 👀 已接收仅用于确有服务端接收证据但未得到更具体状态的情况，不强制每次播放一次。消息ID不匹配时不猜测。
- 本地待发/发送中/确认丢失等使用真实本地发送状态，不冒充Agent接收、执行或失败。网络掉线不能把现有执行状态改成失败。
- 用thread_id、receipt_id、client_message_id建立关联；不靠正文相似、相邻助手消息或话题最新收据推断状态。无收据身份的旧历史不补造成功标记。
- 冷启动/历史加载后读取缺少的可见历史收据；请求有界、可取消，缺失/失败不制造成功状态，不能因渲染重复触发无界请求。

## 展示与操作

- 紧凑reaction样式：表情+短状态文案，不展示人数；不能点击改变执行状态。
- 乐观消息转权威消息保持稳定key及reaction位置；状态更新不强制scrollToEnd、不增发消息。
- 精简重复的任务状态列表和本机发送记录汇总；必要的停止、取消排队、审批/澄清仍可用，操作明确关联对应收据，不能把它们变成表情点击动作。
- 原有键盘/前后台/阅读锚点修复保持；不为reaction引入全局布局动画或新依赖。

## 实现决策（编码前核对）

- 保留旧工作区 WIP 提交，再合入 main 58980ea；以合并后的 ChatTimeline 键盘布局、列表动画和 SDK 收据缓存为准，不新增消息或本地权威状态库。
- 仅用户消息中明确的 receipt_id + client_message_id 与当前 thread_id 三元组，或本机已确认发送记录中的同一三元组可投影收据；缓存中收据身份不匹配时不展示，也不因缓存变化换 FlatList key。已确认但未取到具体状态时，凭服务端接收证据显示已接收；本地发送阶段不伪装 Agent 状态。
- 收据拉取只覆盖当前历史窗口最近 30 个用户身份，最多 3 个并发；窗口/话题切换或离线取消，404 不重试，临时故障在下次重新上线时重试。SDK getReceipt 在校验返回身份后会先写入自己的缓存并通知 React：UI 必须再次核对三元组；取消和迟到结果按代际隔离，不能只依赖 AbortSignal。
- reaction 保留固定行高，状态更新不增删消息、不改变 key；原控制条保留排队取消和停止入口，审批/澄清操作仍是独立交互区，不把表情变成按钮。
- 补充验收：取消键盘上方的本机发送/发布汇总条；消息正文在本机待发、提交中、接收待核对、发送受阻时浅灰，仅服务端明确接受（可靠发送记录已确认或权威消息身份）后恢复正常文字色，不等待 Agent 执行完成；真正的失败仍以消息旁易懂提示及必要操作说明展示。日常网络恢复不暴露同步、收据、内部 ID、令牌、诊断或原始错误；配对、频道、聊天界面仅展示必要、自然的行动引导，不改动安全保存与后台恢复。

## 主控末轮核对

- 正常发送阶段只改变正文颜色，不显示本地状态 reaction 或虚线边框；只有实际无法发送时单独显示自然语言提示。Agent reaction 保持固定位置及紧凑圆角外观。
- 操作区以关联消息摘要区分取消/停止目标，不展示内部 ID；必要审批说明保留原文。
- 连接错误类别只通过开发侧 console.info 输出既有脱敏摘要，不显示在 App；没有远程遥测或新增普通用户诊断入口。
