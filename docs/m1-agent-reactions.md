# M1 Agent 状态 reaction

## 已确认范围

Jamie确认借鉴Discord reaction，主要用于表达Agent真实状态，不做用户emoji选择、计数、点赞或社交功能。展示附着在对应用户消息下，在同一位置更新，不新增状态聊天消息。当前先实现，部署须按明确授权执行。

## 状态与身份约束

- 服务端收据 queued → ⏳ 排队中；running → ⚙️ 处理中；completed → ✅ 已完成；failed → ⚠️ 执行失败；interrupted → ⏹ 已停止；unknown → ⚠️ 结果待确认。
- 对应收据存在pending审批/澄清时显示 ⚠️ 等待审批/等待回答，不能把已结束收据误标为仍待处理。
- 👀 已接收仅用于确有服务端接收证据但未得到更具体状态的情况，不强制每次播放一次。消息ID不匹配时不猜测。
- 本地待发/发送中/确认丢失等使用真实本地发送状态，不冒充Agent接收、执行或失败。网络掉线不能把现有执行状态改成失败。
- 用thread_id、receipt_id、client_message_id建立关联；不靠正文相似、相邻助手消息或话题最新收据推断状态。无收据身份的旧历史不补造成功标记。
- 冷启动/历史加载后读取缺少的可见历史收据；请求有界、可取消，缺失/失败不制造成功状态，不能因渲染重复触发无界请求。

## 展示与操作

- 紧凑reaction样式：表情+短状态文案，不展示人数；不能点击改变执行状态。
- 乐观消息转权威消息保持稳定key及reaction位置；状态更新不强制scrollToEnd、不增发消息。
- 精简重复的任务状态列表和本机发送记录汇总；必要的停止、取消排队、审批/澄清仍可用，操作明确关联对应收据，不能把它们变成表情点击动作。
- 原有键盘/前后台/阅读锚点修复保持；不为reaction引入全局布局动画或新依赖。

## 验收

状态全覆盖、审批/终态优先级、同文不同消息、跨话题或收据不匹配、离线不等于失败、冷历史收据补齐、乐观确认后不重复；手机测试、TypeScript、双平台导出。真机视觉与连续操作另行验收。
