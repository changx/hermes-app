# 网络恢复优化与消息时间

## 已确认行为

Jamie 要求保留网络失败处理优化，并在每条完整消息的发送者旁显示时间。界面和提示继续使用英文。

- 最新要求覆盖早期秒级方案：按设备本地时区显示，不足一分钟精确显示 `<1m`，不足 60 分钟 `12m ago`，不足 24 小时 `3h ago`，达到 24 小时显示 `MM/DD HH:mm`，24 小时制；辅助阅读绝对时间同样只到分钟。
- 时间对应原始消息，不使用重连、读取、收据状态更新或压缩发生的时间。时间只用于显示；人类展示引用顺序与模型 context 顺序不变。
- 连续 assistant 片段沿用现有完整消息分组，不为片段重复显示发送者与时间。未知旧数据不编造当前时间。
- 等待发送的本机消息创建时只取一次时间，随 outbox 保存；重试/冷启动不重新取时。服务端返回原始权威时间后，以服务端字段为准。
- 相对时间每 60,000ms 更新一次，不在秒/分/小时边界额外排短定时器。后台/失活暂停，卸载清理；前台恢复或新权威时间到达时立即更新，随后恢复一分钟周期。未知和已使用绝对格式的旧消息不排无用定时器，不重绘整条 Markdown/列表或改变阅读位置。

## 时间契约

`Message.created_at?: number`：非负且有限的 UNIX 秒，可带小数，最大 `8.64e12`（JavaScript Date 支持范围）。普通消息来自 Hermes 原始消息 timestamp；App 原始用户输入来自对应收据的首次 created_at。历史、搜索、最新分页、冷读一致。缺失则省略，不做数据库回填或数据迁移。SDK 兼容旧服务端省略，拒绝畸形值，不按该字段排序。

## 网络检查结论与优化边界

旧 SDK 的无声断线检测先等一次存活周期，等待 HTTP 回放后才发 ping，随后再等一个周期才检查 pong；回放等待会继续拉长检测。这是源码确认的等待路径，不代表已抓到用户手机某一次断线的日志。

优化复用现有连接、探测、重试与 outbox 机制：缩短探测周期，使缺失 pong 的期限不受 HTTP 回放拖延。认证失败仍停止盲重试，429 继续遵守 Retry-After，发送使用同 ID 和原文幂等重试，执行结果 unknown 不重跑。不增加网络依赖或修改 Hermes 核心。具体完成后的参数和测试结果另记。
