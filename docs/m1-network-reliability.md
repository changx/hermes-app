# M1 网络可靠性：首版交付门槛

Jamie 要求网络通信保障和重试在首版完善，优先于继续扩展视觉功能。本文是验收要求和代码检查记录，不是功能完成报告。

## 默认自动处理，尽量不打扰用户

Jamie 明确要求通信恢复尽可能不打扰用户，不把技术判断交给用户。

- 断线、切网、暂时超时、确认丢失默认自动重连、查询收据、同ID原文安全重试和补齐；不能要求用户选择“重试还是放弃”、判断是否已接收或点击“重建同步”才能继续使用。
- 可恢复的临时故障使用轻量状态（如等待网络、正在恢复），不反复弹窗、不堆技术错误、不打断输入和阅读；恢复成功自动消退。手动重试只是可选快捷操作，不是必经步骤。
- 最新确认：网络状态必须告知用户，而不是要求用户解决。手机先使用顶部 toast，明确显示当前正在重试或多少秒后自动重试；不提供重试/放弃按钮，不拦截输入。倒计时必须来自真实重试调度，不能用界面假计时；没有计划重试的授权/协议失败不能写成正在重试。
- 对可验证属于当前服务器/身份的过期同步游标，自动重建投影并保留待发记录及阅读位置；异常或身份不匹配游标不得静默跨身份使用。
- 执行结果不明时先自动核对权威收据与历史；无法确认时保留记录、明确状态，不自动创建新执行，也不要求用户猜测是否重跑。需要用户明确发起的全新执行不能冒充通信恢复。
- 用户不负责查找、复制或修复令牌。初次接入使用管理员授权的一次性设备配对，设备认证由App安全保存；正常重连/重启不重新配对，不建立无必要的账号或刷新令牌平台。已有开发凭据继续兼容，不借此旋转现有凭据。
- 服务端认证故障由系统/运维处理；只有明确撤销授权等无法自动恢复的情况才提供可完成的重新配对流程，不能自动恢复被撤销权限。存储故障须明确说明尚未保存，保留输入，不给技术选项菜单、不隐瞒失败。
- 配对：最小一次性配对协议、独立设备凭据与撤销、手机入口去除原始令牌输入；纳入R4验收。此轮实现只改隔离源代码，不更改运行环境认证配置。
- R4验收增加：正常网络故障恢复全程零必需点击、无决策弹窗，不需要用户理解收据/游标/幂等；确需介入的异常提示准确且不重复骚扰。

## 任务与执行顺序

归属：原 P2-01 网络工作，范围已提前至 M1。

- R1：自动重连、请求/握手超时、半开检测、退避抖动、真实连接状态。初连和回前台失败也必须能自行恢复；提供立即重试；401/403停止盲重试，429遵从服务端重试间隔。
- R2：待发消息先持久保存，再进行网络发送；原文和ID保持不变，身份隔离；ACK丢失安全重试、自动和手动重试互斥，连续点击不得重复执行。存储失败不误报成功，较早未确认记录不能被下一条覆盖。
- R3：断线补齐、前后台竞态、冷启动恢复、已结束收据查询、事件游标失效恢复及消息身份合并。恢复不抢阅读位置、不跨身份串缓存。
- R4：网络故障矩阵与iPhone真机验收，依赖R1/R2/R3。R4 通过后网络工作才完成；M1 等待网络工作完成。

最小实现从R1启动，沿用共享HermesClient、现有插件及原生存储。R2/R3补实际缺口，不另建通用通信平台，不修改Hermes核心。开发部署单独依据授权；本轮已获授权更新隔离开发环境，未修改主实例或固定核心。

## 实现状态

### 顶部网络状态 toast 候选

隔离分支 `feat/network-status-toast`，基线 `b2e42ed`。手机所有路由共用一个账号级顶部 toast：初连显示 `Connecting…`；正在尝试显示 `Retrying connection…`；等待时显示 `Connection interrupted. Retrying in Ns…`；核对目录时显示 `Restoring connection…`。连接恢复立即消失，后台暂停隐藏；授权拒绝和不可重试失败显示实际结果，不编造重试计划。没有按钮、自动跳转或触摸拦截；倒计时只更新 toast，不写聊天内容。

共享 LiveSessionClient 提供 `nextRetryAt` 和 `onRetryScheduled`，在下一次尝试、暂停和关闭时清除。429 等待采用实际退避和服务端 `Retry-After` 的较大值。保留401/403停止重试及存活页面现场。桌面 UI、插件、核心和依赖锁不变。

自动检查：共享 SDK 128项通过；手机551项通过、1项跳过；共享与手机 TypeScript 6.0.3通过；iOS/Android实际导出并从各自metadata指定的精确bundle核对提示文案与调度字段。生产组件测试覆盖倒计时、定时器清理、无交互和跨页面共享；生产SDK故障注入覆盖429等待、暂停取消、401/403及协议失败不安排重试。测试使用合成故障，不等于真机或公网验收。

未合入 main、未发布或重启服务；iPhone顶部位置、原生导航覆盖和键盘实测待验收。此前目录恢复检查发现的损坏503 JSON停止恢复及旧目录覆盖新运行状态问题未在本候选修复。证据在本Channel私有workspace `network-status-toast/`。

## 必测故障窗口与预期

1. 接收前断网：本地消息可恢复，显示待发送/等待网络；恢复后安全提交。
2. 服务端已接收但ACK丢失：原ID原文重试只关联原收据，不新增消息或执行。
3. 执行中断线或切后台：服务端执行继续；回前台补齐状态，不重新提交任务。
4. 已完成但通知丢失：重连、冷启动均找回最终消息及终态，不能一直显示执行中。

上述窗口结合断网、弱网、Wi-Fi/蜂窝切换、后台、系统杀进程、服务重启、游标过期和多次点击重试验证；另测401/403、429/5xx、请求悬挂与WS半开。

- 网络错误与鉴权、协议、业务拒绝分开，不能无限重试全部错误。
- 区分本地保存、等待网络、提交结果不明、服务端已接收、执行中和终态；已接收不代表已完成。
- 自动重试针对可安全重放的请求；执行unknown不自动重新运行。停止/审批/频道创建等写操作不可套用无差别POST重试。
- 历史、状态与已读以服务端为准；客户端缓存仅用于恢复和展示；退出或换身份不能携带旧消息到新连接。
- 不要求iOS后台长期维持WS，也不以系统推送作为本轮前置；要求服务端执行与回前台恢复可靠。
