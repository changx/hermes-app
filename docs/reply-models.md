# 回复显示生成模型

## 需求

Jamie 确认：

- 每条最终回复的消息工具栏最右侧显示生成它的模型。桌面和手机都显示。
- 显示原始模型 ID（例如 `claude-opus-5-5`），不维护易读名称对照表。
- 功能上线前的旧回复不显示模型，不用 session 级模型补写。
- 只要求通过 Hermes App 发出的消息有模型；cron 等核心直接发起、平台不是 `hermes_app` 的回复可以没有。

## 数据来源

- Hermes 核心 `messages` 表没有每条消息的模型；`sessions.model` 是 session 级，中途 `/model` 切换后不能代表每条回复。
- 核心 turn finalizer 在每轮结束时调用 `post_llm_call`，参数含 `model=agent.model`。发生 provider 备用切换时 `agent.model` 已是备用模型，所以它是这一轮最后实际使用的模型。
- 插件在 `post_llm_call`（仅 `platform == 'hermes_app'`）中把 `turn_id → model` 写入插件自有表 `reply_models`，首次写入为准，并发布一条 message 同步事件，让已打开的页面重新读取。不修改核心。
- 历史、单条引用、窗口及搜索响应中，`display_kind == 'final'` 的回复带可选字段 `model`。capability `message_models: true`。
- 模型 ID 与可选择模型使用同一字符规则（`[A-Za-z0-9][A-Za-z0-9_./:+-]{0,255}`，不含 `//`、`://`）。服务端不记录、客户端丢弃不合规值，不显示也不报错。

## 客户端

- 共享客户端 `validMessage` 只给最终回复保留合规的 `model`。
- 桌面：`MessageToolbar` 最右侧 `.message-model`，`margin-left: auto`，标签色、字号随字号设置（比正文小 2px），单行省略，悬停显示 `Generated by <model>`。
- 手机：`MessageToolbar` 最右侧单行浅灰文字（`#8a94a0`，12），无障碍标签 `Generated by <model>`。`ChatTimeline` 的行比较加入 `model`，稍后到达的模型能显示。

## 验证

- 插件：最终回复在历史与搜索中带模型；用户输入和过程行不带；发布一条 message 事件；重复调用不改写；不合规或未知 turn 不记录；其他平台不记录。
- 共享客户端：最终回复保留合规模型；非最终行和不合规值丢弃。
- 手机：工具栏最后一项为模型、单行、无障碍标签正确；无模型不显示；时间线行携带模型。
- 桌面 Chromium：模型位于工具栏最右端（误差 ≤1px），与按钮垂直居中，颜色与按钮标签相同；无模型的回复不显示。
- 上述客户端测试去掉产品改动后均失败。

## 待验收

插件安装、Gateway 重启后的真实模型消息，以及 Mac 和 iPhone 真机显示。
