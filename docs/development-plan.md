## P0：最小端到端技术验证

目的：先验证能否复用已有能力，不先做大规模 UI 或数据重构。

工作：
- 记录 Hermes、shared、Desktop 的源码版本和接口契约。
- 验证 plugin 能否通过已有接口和正式扩展点承接通信、执行、历史、提示及同步需求；既有探针证明的核心能力不等于插件可接入性。发现缺口先报告，不修改 Hermes 核心。
- 隔离配置/数据库，用两个最小客户端验证会话、历史、异步事件。
- 验证常规压缩、idle compaction、session 续接前后的用户历史。
- 验证最后一个客户端离线后的执行/审批生命周期、回放缓存耗尽和重启。
- 验证 Channel 说明在 Session 创建时进入头部上下文，且压缩/恢复/续接后插件不再补入；沿用 Hermes 压缩后的上下文，不要求 Description 原文保留。确认 Project 映射和最小缺口。
- 验证桌面代码复用与手机独立容器的键盘、长列表、附件、通知能力边界。

交付：实际运行结果、缺口清单、明确的技术选型和下一阶段工期估计。未授权真实付费模型调用时使用隔离测试替身，并明确哪些模型/压缩行为尚未实测。

退出条件：每项关键保证都有证据或可执行的修补方案，不以 WebSocket 握手成功代表整体可行。

## P1：Hermes plugin 数据与同步扩展

工作：通过独立维护的 Hermes plugin 和已有接口实现 Channel/Thread、公共提示继承、连续历史、稳定消息身份、发送接收确认及重试、快照与增量同步、阅读状态、后台结果投递、持久任务生命周期与认证范围。不修改核心源码，不用 monkey patch 或客户端专用 fork 绕过限制。

交付：插件包、版本化接口契约、必要的插件自有元数据 schema/迁移方案、隔离自动化测试；不擅自修改核心数据库 schema，保持现有 Discord/Telegram 与其他 profile 行为不变。是否实际安装或部署插件另行授权。

## P2：共享客户端与双端应用

工作：共享连接/状态/缓存逻辑，Channel/Thread 管理、消息和附件、执行交互、搜索及未读；独立桌面和手机应用壳、原生通知、凭据保存和平台交互。

依赖：核心接口稳定后双端可并行。手机原生能力早期验证，不等桌面全部做完才开始。

交付：可安装的桌面/手机测试包，而不是网页链接。具体 OS 范围在开始该阶段前确认。

## P3：真实设备验收与发布准备

工作：真实网络/后台/系统终止测试、大量历史性能、升级迁移、消息一致性、签名/更新/分发。公开发布与生产部署单独获得授权。

交付：安装包、版本标识、设备/系统清单、测试报告、已知限制与回退方式。

## 验收矩阵

- A01（R01）：批准范围内桌面与手机均能独立安装、启动和连接；Web/PWA 不替代手机 App。
- A02（R02/R03）：创建两个同 Channel Thread，共用必要说明但讨论历史隔离；跨 Channel 不串提示。
- A03（R03/R04）：只有全新会话头部注入一次 Channel 说明；续聊、时间/长度压缩、idle compaction、冷恢复和物理 successor 均不得触发插件补入。沿用 Hermes 自己处理的上下文，普通正文没有说明副本。
- A04（R04）：压缩前后的原始用户可见消息逐项一致；实时最终结果与冷启动历史一致。
- A05（R04/R05）：双端在线新增消息及变更一致；重复/乱序事件不产生重复正文。
- A06（R05）：发送接收后关闭全部客户端，正常任务继续；重新打开可补齐完整结果。
- A07（R05）：服务已接收但响应丢失时重试，仅一条用户消息和一次执行；另一次新发送不被旧幂等键吞掉。
- A08（R05）：长时间离线超过回放缓存、服务重启后仍可同步历史及准确执行状态；不擅自重复执行有副作用动作。
- A09（R05）：定时/后台消息在离线期间写入正确 Thread；恢复后可见，通知点击定位正确。
- A10（R05）：两端同时处理审批，最多一次生效；已处理/过期请求不再执行；离线恢复待回答问题。
- A11（R05）：一端已读后另一端同步，不能因乱序更新使已读位置倒退。
- A12（R01/R06）：手机退后台、被系统终止、重启后能恢复同步；附件不依赖桌面本地路径。
- A13（R06）：跨 profile/连接身份的数据隔离；凭据不写入仓库/日志/通知正文。
- A14（R07）：现有 adapter/其他 profile 回归通过；没有 Discord 兼容服务或第二套权威业务存储。
- A15（R08）：在未为客户端修改核心的 Hermes 基线上安装并验证 plugin；核心源码无客户端补丁、无 monkey patch/替换核心模块。禁用插件后原有功能保持可用；未覆盖的扩展点明确列为阻塞项。

每项记录版本、步骤、预期、实际结果与证据。未测标为未测，不用 mock 结果冒充真实网络、模型或设备结果。
