## Product contract (confirmed)

2026-10-02 amendment: [shared completed-unread directory status](completed-unread-directory.md) is a narrow exception to the original no-read-reporting scope below. Lightweight result/read metadata belongs to the directory subscription; a foreground visible-result acknowledgement clears it across devices. No message unread counts, general read position, background bodies, replay or history cache return.

- No unread counts or cross-device read-position reporting for unread accounting.
- Only lightweight Channel/session directory and running state remain resident outside a conversation.
- All living conversation pages own content and concurrent subscriptions. Running-but-unopened conversations do not preload content. See [live session pages](live-session-pages.md), which supersedes the original single-owner implementation below.
- Native Stack owns mount/unmount. Focus and coverage govern visible work only. Opening B does not release A. Returning to an existing page preserves its scene and removes pages above it. Page uniqueness is connection identity plus stable Thread ID within one client. Actual destruction, identity loss or authoritative unavailability releases only the affected page. Late replies cannot repopulate released content.
- Backgrounding retains every living page, including its loaded window, scroll/follow state, drafts, files and reader/media scene. Suspend transport and reads; recovery reconciles each retained window without remounting or jumping to latest. Process death still has no persisted server history.
- No client SQLite history database, event replay, timestamp alignment, per-entity sync version chain or periodic business reads. A normal heartbeat detects a broken connection; it does not read catalogue or messages.
- Initial open, reconnect and foreground recovery retrieve fresh current state. Subscribe acknowledgement must precede the initial content read; events during that read request another reconciliation so there is no handoff gap.
- Server owns all original history and accepted tasks; leaving/closing the App never cancels an accepted model task. Preserve stable message IDs/order, public tool records, latest/older pagination, approvals and attachment security.
- Credentials and unconfirmed sends retain secure durable storage. Drafts/unsent originals must not be silently deleted. Authenticated durable matching ACK proves receipt independently of execution outcome; unknown execution is never re-run automatically.
- Existing archive versus hard-delete product contract is unchanged. Directory removal/archive makes an opened target unavailable and blocks new delivery, retaining local user input for recovery.
- Offline restart has no stored server history; this is an accepted tradeoff, not a defect to hide with a new database.

## Simplest wire boundary

The account-network candidate uses one WebSocket and one directory per account, with concurrent scoped subscriptions for living pages. It requires the paired plugin's `multi_session_live:true` hello. Legacy clients retain their single-watch semantics against that plugin; new clients reject an older plugin explicitly rather than maintaining a second transport architecture. Historical work breakdown below describes the earlier single-owner release.

Reuse existing authenticated capabilities/history/receipt/interaction/attachment APIs. Catalogue contains only directory fields and running state (no unread counts, receipt bodies, prompts or messages). The account connection observes directory/running changes and content hints for its living pages. Frames remain change hints, not replay instructions. No client event cursor, data-version chain or history store is introduced.

`GET /v1/catalogue?after=<ordinary page anchor>&limit=30` returns directory items and next_after; full pagination must succeed before applying absence. Ordinary history/catalogue pagination is not a synchronization cursor.

`WS /v1/live`: hello; `{type:watch,thread_id:<id|null>,request_id:<ephemeral request identity>}`; matching watching acknowledgement; directory_changed, session_state (running), conversation_changed scoped to the watched request. Request identity is only to ignore stale subscription responses, not a stored entity version. Ping/pong is health-only. Slow consumers close/reconnect instead of silently dropping required changes.

The candidate hello adds `multi_session_live:true`. `watch` without `mode` still replaces all subscriptions, including clearing them with `thread_id:null`. `mode:add` installs/replaces the given Thread's subscription without touching others. `mode:remove` removes only the matching Thread/request identity and needs no acknowledgement. Each command carries one Thread, not an unbounded batch. The server validates existence/access on subscription and retains authentication, input-size, buffer and scoped-state limits.

Capabilities and socket establishment run concurrently. A matching subscription acknowledgement still precedes body reads. Initial history and live-state then run concurrently. `openConversation` accepts a fourth, content-ready callback for first UI release; its Promise still waits for history and state. Returning to an already content-ready opening invokes the current callback immediately. Initial-history readiness is recorded before state completes, so reconnect does not reset a shown window to latest. Neither UI invents receipts, approvals or an idle result while status is pending.

A non-retryable page read/source error pauses only that page's subscription and retains its scene; explicit reopening can retry it. It does not close the account or other pages. Authentication failures and shared transport recovery remain account-owned. No separate page retry framework is added.

`GET /v1/threads/{id}/live-state` provides only the opened conversation's receipts/approvals; outer catalogue never includes these bodies. `GET /v1/channels/{id}` provides temporary editor detail rather than storing descriptions in the directory.

Plugin-owned Store post-commit notifications wake the publisher, including writes through formal history hooks; never notify before a failed/rolled-back write. Reuse existing server metadata/change records privately for reliable publication; do not add another authoritative store or make clients replay it. Old /snapshot,/sync,/events remain server-compatible for already published clients until their upgrade; candidate apps use only the new scoped path.
